# Analyst Worker

Analyst — воркер, который анализирует цели и разрабатывает новые подзадачи.
Он работает с контрактами роли `Analyst`, обращается к Planner за методами и
формирует дочерние контракты.

## Обязанности
- Получать контракты `contracts.analyze` и вытягивать контекст из Blackboard.
- Выбирать подходящие HTN‑методы (через библиотеку `libs/htn`).
- Создавать новые подцели и публиковать их в Contract Manager.
- Вести отчёт о потреблённом бюджете и глубине декомпозиции.

## Структура
- `analyst/worker.py` — точка входа (цикл обработки событий).
- `analyst/adapters/` — место для клиентов Blackboard, Planner и Registry.
- Планируется каталог `strategies/` для доменных эвристик.

## Конфигурация
| Переменная | Назначение |
|------------|------------|
| `ROLE` | Значение `ANALYST` (используется для логов/метрик). |
| `DATABASE_URL` | История планов (чтение). |
| `NATS_URL` | Подписка на контракты и публикация новых задач. |
| `REDIS_URL` | Кеширование методов/эвристик. |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | Трейсы (`analyst.plan_step`). |

## Запуск
```bash
cd apps/workers/analyst
python -m analyst.worker
```
Понадобится запущенный Planner и инфраструктура `make up`.

## Метрики/логи
- `analyst_subtasks_total` — количество созданных подзадач (добавить).
- `analyst_replan_total` — число репланов по причинам.
- Логи: фиксируйте `goal_id`, `method_id`, `budget_allocated`.
