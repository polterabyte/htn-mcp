# Orchestrator Service

Оркестратор — входная точка всей многоагентной системы. Он принимает цели от
пользователей, валидирует их, запускает HTN‑планирование и публикует контракты
для воркеров через шину событий. Сервис построен на FastAPI и экспонирует
стандартный HTTP API.

## Быстрая навигация по коду
- `orchestrator/main.py` — инициализация FastAPI, метрики Prometheus, базовые
  маршруты `/health` и `/metrics`.
- `orchestrator/api/goals.py` — обработчик REST‑эндпоинта для постановки целей.
- `orchestrator/domain/` — (заглушка) место для схем целей, контрактов и SLA.
- `orchestrator/adapters/` — клиенты к инфраструктуре (БД, очереди, хранилище).
- `orchestrator/services/` — бизнес‑логика создания планов и публикации
  контрактов.

## API
| Метод | Путь | Описание |
|-------|------|----------|
| `POST` | `/api/v1/goals/` | Принять новую цель. Тело — `GoalPayload` с именем,
описанием и контекстом. Возвращает `202 Accepted` и идентификатор цели. |
| `GET` | `/health` | Простой health‑check для балансировщиков. |
| `GET` | `/metrics` | Prometheus метрики (HTTP счётчик `http_requests_total`). |

В перспективе здесь появятся эндпоинты управления планами (`/plans/{id}`) и
админские методы для реестра MCP.

## Конфигурация
| Переменная | Назначение | Значение по умолчанию в `docker-compose.yml` |
|------------|------------|---------------------------------------------|
| `DATABASE_URL` | Подключение к Postgres с метаданными планов и контрактов. | `postgresql://postgres:postgres@postgres:5432/orchestrator` |
| `REDIS_URL` | Кэш/быстрая синхронизация. | `redis://redis:6379/0` |
| `NATS_URL` | Шина событий для контрактов и планов. | `nats://nats:4222` |
| `S3_ENDPOINT`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET` | Объектное хранилище артефактов (MinIO/S3). | см. compose (`http://minio:9000`, `minio`, `minio123`, `artifacts`) |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | Экспорт трейсов/метрик в OTEL‑коллектор. | `http://otel-collector:4317` |

## Запуск локально
1. **Полный стек:** `make up` поднимет Postgres, Redis, NATS, MinIO и сам
   оркестратор с воркерами.
2. **Только API:**
   ```bash
   cd apps/orchestrator
   uvicorn orchestrator.main:app --reload --port 8080
   ```
   Предварительно экспортируйте переменные окружения или создайте `.env`.
3. **Тесты:** (заглушка) планируется `pytest`. На данный момент автоматических
   тестов нет — добавляйте их при расширении API.

## Интеграции
- **Planner** — вызывается через очередь/HTTP для построения HTN‑плана.
- **Contract Manager** — получает созданные контракты и отслеживает статус.
- **Workers** — подписываются на контракты, созданные оркестратором.
- **Blackboard** — хранит общий контекст. Оркестратор пишет начальные факты.
- **MCP Registry** — источник прав доступа к инструментам для листовых задач.

## Наблюдаемость
- Метрики доступны по `/metrics` (Prometheus).
- Трейсы отправляются через OTLP (`OTEL_EXPORTER_OTLP_ENDPOINT`).
- Логи рекомендуется делать структурированными (JSON) и проксировать в Loki.

## Что доработать в первую очередь
- Добавить Pydantic‑схемы и валидацию payload'ов.
- Реализовать публикацию целей в NATS (`contracts.*` и `plans.*`).
- Расширить API управлением планами и статусами (`/plans/{id}`).
- Покрыть критичную логику тестами и описать сценарии в `docs/RUNBOOKS.md`.
